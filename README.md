# Чат «заказчик ↔ исполнитель» в стиле Telegram

Модуль личных сообщений для самописного сайта на **PHP 8 + MySQL**.
Внешний вид и логика — как в Telegram: список диалогов, пузыри сообщений,
галочки ✓/✓✓, «печатает…», счётчики непрочитанного, онлайн-статусы, вложения.

Транспорт — AJAX-поллинг (3 сек): работает на любом хостинге, включая shared,
никаких демонов и Node.js. При росте нагрузки API не меняется — достаточно
заменить поллинг на SSE/WebSocket (см. «Дальнейшее развитие»).

## Состав

```
chat/
├── chat-page.php   — пример готовой страницы чата
├── api.php         — JSON-API (sync / send / start / typing / history)
├── file.php        — безопасная отдача вложений (только участникам диалога)
├── helpers.php     — БД, авторизация, пользователи
├── config.php      — настройки (БД, интеграция, вложения)
├── install.sql     — таблицы + демо-данные
├── assets/
│   ├── chat.css    — стили (тема Telegram)
│   └── chat.js     — виджет (vanilla JS, без зависимостей)
├── uploads/chat/   — вложения (доступ извне закрыт .htaccess)
└── demo.html       — интерактивное демо интерфейса без PHP (откройте в браузере)
```

## Установка (5 минут)

1. Скопируйте папку `chat/` в корень сайта.
2. Выполните `install.sql` в базе сайта (4 таблицы с префиксом `chat_`).
3. В `config.php` укажите данные БД.
4. Откройте `chat/chat-page.php?act_as=1` — работает демо-вход
   (переключение пользователей вверху страницы: Анна ↔ Игорь ↔ Максим).
5. Проверьте переписку в двух браузерах под разными `act_as`.

## Интеграция с сайтом (продакшен)

**Авторизация.** В `config.php` поставьте `'demo_auth' => false`, затем в
`helpers.php` в функции `chat_current_user_id()` раскомментируйте возврат
id из вашей сессии:

```php
return isset($_SESSION['user_id']) ? (int)$_SESSION['user_id'] : null;
```

**Имена пользователей.** В `config.php` укажите вашу таблицу:
`'users_table' => 'users', 'users_name_col' => 'name'`
(или перепишите `chat_user_info()` под свою структуру/Join с ролью).

**Страница чата.** Минимум кода в любом месте сайта:

```html
<link rel="stylesheet" href="/chat/assets/chat.css">
<div id="chat" style="height:calc(100vh - 60px)"></div>
<script src="/chat/assets/chat.js"></script>
<script>ChatWidget.mount(document.getElementById('chat'), { api: '/chat/api.php' });</script>
```

**Кнопка «Написать исполнителю»** на странице заказа — диалог 1-на-1
находится или создаётся автоматически (как «личка» в Telegram):

```js
ChatWidget.openWith(userId, 'Заказ №128 — логотип');
```

## Как устроено

| Таблица | Назначение |
|---|---|
| `chat_threads` | Диалоги (+ тема/№ заказа) |
| `chat_participants` | Участники, `last_read` (галочки ✓✓), `typing_until` («печатает…») |
| `chat_messages` | Сообщения и вложения |
| `chat_presence` | Онлайн-статус («в сети» = был запрос за 60 сек) |

API: `sync` (диалоги + новые сообщения открытого чата, метка «прочитано»,
когда вкладка активна), `send` (текст/файл), `start` (найти/создать диалог),
`typing`, `history` (подгрузка старых сообщений при прокрутке вверх).

Вложения: до 10 МБ, whitelist расширений (config), картинки показываются
в пузыре, документы — карточкой; отдаются только участникам через `file.php`.

## Безопасность — проверить перед продакшеном

- Все запросы к API идут через PDO prepared statements.
- Доступ к диалогу/файлу — только участникам (`chat_is_participant`).
- Вывод в JS — везде экранирование (`esc()`), XSS исключён.
- `uploads/` закрыт `.htaccess`; для **nginx** добавьте `location /chat/uploads/ { deny all; }`.
- API меняет состояние методом POST — если у вас строгие требования,
  добавьте CSRF-токен в POST-запросы и проверку `Referer`.
- Рекомендуется вынести `uploads_dir` за пределы веб-корня.

## Дальнейшее развитие (по мере роста)

- **Реалтайм вместо поллинга**: поднять Centrifugo или Ratchet WebSocket и
  дергать фронтенд событием «есть новые» — `chat.js` достаточно слегка
  доработать (заменить `tick()` на подписку). Логика и БД не меняются.
- Групповые чаты: схема уже поддерживает N участников (список диалогов
  берёт «первого другого» — при группах расширить до списка).
- Уведомления о новом сообщении на email/Telegram-бот (через cron: выборка
  сообщений старше N минут без прочтения).
- Удаление/редактирование сообщений, реакции, аватарки из профиля.

## Требования

PHP ≥ 8.0 (PDO mysql, json, fileinfo — стандартно), MySQL/MariaDB.
Часовой пояс PHP и MySQL синхронизируется автоматически (`config: timezone`).
